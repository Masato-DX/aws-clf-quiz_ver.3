# 要件定義書 — ウェブ解析士 認定試験 対策クイズ

> **このドキュメントの目的**
> 本アプリの仕様を、AI エージェントが単独で読んで再実装できる粒度で記述する。
> 実装の詳細（アルゴリズム・データ構造・画面構成）は `docs/design.md` を参照。

---

## 0. 一読して掴むべきこと

| 観点 | 内容 |
|---|---|
| 何のアプリか | ウェブ解析士認定試験の四択／複数選択クイズを解き、**間違えた問題を自動追跡して復習に誘導**する学習アプリ |
| 誰が使うか | 受験者本人（単一ユーザー、認証なし） |
| 動作形態 | ブラウザ完結の SPA。スマホにインストールして使う PWA |
| サーバ | **なし**。データは localStorage、任意で GitHub Gist に同期 |
| 収録数 | 320問（公式テキスト2026 第17版の全8章 × 5領域 × 3難易度） |
| 由来 | AWS CLF-C02 対策アプリ（合格実績あり）の学習アルゴリズムを仕様を変えずに移植 |

**このアプリの本質的価値は「問題を出す」ことではなく「同じ問題を無駄に繰り返させない出題制御」にある。**
この学習アルゴリズム（§4）を削ると、ただの問題集になり価値が大きく落ちる。

## 1. 対象試験

| 項目 | 内容 |
|---|---|
| 試験名 | ウェブ解析士認定試験（一般社団法人ウェブ解析士協会） |
| 位置づけ | WACA 資格体系の入口（旧「初級ウェブ解析士」） |
| 出題形式 | 四肢択一・60問／60分（2026年1月以降） |
| 受験方法 | オンライン（自宅PC）・公式テキスト持ち込み可 |
| 出題方式 | 公式テキストの**各章からランダム出題** |
| 合格ライン | **70%**（協会は公式に点数を公表していないため通説値を採用。アプリ内に注記あり） |
| 準拠教材 | ウェブ解析士認定試験 公式テキスト2026（第17版）／全8章 |

### 1.1 出題の性質（設計上の前提）

テキスト持ち込みが可能な試験のため、**検索すれば分かる単純暗記より、判断力と計算力が問われる**。
本アプリはその性質に合わせて次の配分にしている。

| 問題タイプ | 内容 | 配分の方針 |
|---|---|---|
| 暗記型 | 用語・定義・フレームワークの構成要素 | 初級を中心に配置 |
| **計算型** | CVR・CPA・CPC・CTR・CPM・ROAS・ROI・LTV・客単価の算出と逆算 | **約20%（60〜70問）を確保** |
| 判断型 | 実務ケースでの解釈・優先順位・切り分け | 中級・上級の中心 |

## 2. スコープ

### 2.1 対象

- ウェブ解析士認定試験に対する、選択式問題の反復学習
- 学習履歴の記録と可視化
- 複数端末間でのデータ同期（任意機能）

### 2.2 対象外（意図的に作らない）

| 項目 | 理由 |
|---|---|
| ユーザー認証・アカウント | 単一ユーザー前提。認証基盤の運用コストを避ける |
| バックエンドサーバ | 静的ホスティングのみで完結させる |
| 問題データの管理画面 | 問題はソースコード内の配列。Git で管理する |
| 本番試験の時間制限モード | 学習用途に特化。模試機能は現状スコープ外 |
| 複数ユーザーの成績比較 | 個人学習ツールのため |

## 3. 機能要件

### 3.1 画面構成

5 画面。単一の React 状態 `screen` で切り替える（ルーティングライブラリ不使用）。

| ID | 画面 | 役割 |
|---|---|---|
| S-1 | `auth` | 初回のみ。Gist 同期設定（PAT・Gist ID）の入力、または同期なしで開始 |
| S-2 | `setup` | 出題条件の選択とクイズ開始。復習モードの入口 |
| S-3 | `quiz` | 出題・解答・正誤フィードバック |
| S-4 | `result` | セッション結果のサマリ |
| S-5 | `history` | 学習レポート（全履歴の分析） |

遷移：

```
起動 ─┬─ 同期設定あり／同期なしを選択済み ──→ [setup]
      └─ 未設定 ──→ [auth] ──保存 or スキップ──→ [setup]

[setup] ──開始──→ [quiz] ──全問終了──→ [result] ──→ [setup]
[setup] ←──────────────────────────────→ [history]
[setup] ──「設定する」──→ [auth]
```

> **移植元からの変更点**：移植元は PAT を設定するまで setup へ進めなかった。
> 本アプリは「同期せずにこの端末だけで使う」を選択でき、その選択を永続化する（`webanalyst_auth_dismissed`）。
> セットアップ画面からいつでも同期設定を開き直せる。

### 3.2 出題条件の指定（S-2）

| 項目 | 選択肢 | 既定値 |
|---|---|---|
| 難易度 | すべて / 初級 / 中級 / 上級 | すべて |
| 絞り込み軸 | **領域** または **章**（トグルで排他切替） | 領域 |
| 領域 | すべて + 5領域 | すべて |
| 章 | すべて + 第1〜8章 | すべて |
| 問題数 | 5 / 10 / 15 / 20 | 10 |

- 条件に合致する問題数（利用可能数）と、うち未出題の問題数をリアルタイム表示する。
- 苦手問題を保持している場合、「通常出題では後回しになる」旨を注記する。
- 同期が未設定の場合、記録がこの端末にのみ保存される旨を注記する。

### 3.3 復習モード（S-2 の専用入口）

通常出題とは独立した導線として、設定画面の上部にカードを置く。

| ID | 名称 | 出題対象 | 表示条件 |
|---|---|---|---|
| F-1 | 要注意問題（複数回ミス） | 累積誤答 2 回以上の問題 | 該当が 1 問以上 |
| F-2 | 苦手問題に再挑戦 | 現在「間違えたまま」の問題 | 該当が 1 問以上 |

- 難易度・領域の絞り込みは**適用しない**（苦手は苦手として横断的に出す）。
- 問題数の指定も適用せず、**該当する全問**を出題する。

### 3.4 クイズ進行（S-3）

| ID | 要件 |
|---|---|
| Q-1 | 1 問ずつ表示。進捗（現在位置／総数）とプログレスバーを常時表示 |
| Q-2 | 単一選択・複数選択の両方に対応。複数選択問題は問題文とバッジの両方に明記 |
| Q-3 | **選択肢を選んだだけでは正誤を表示しない。「確認する」ボタンの押下で初めて答え合わせを行う**（単一選択も同様） |
| Q-4 | 未選択の状態では確認ボタンを表示しない |
| Q-5 | 答え合わせ後、正解／誤答の色分け、正解の明示、解説文を表示 |
| Q-6 | 答え合わせ後は選択を変更できない |
| Q-7 | 選択肢の並び順は出題ごとにシャッフルする（正解位置の記憶を防ぐ） |
| Q-8 | 部分点なし。複数選択は完全一致のみ正解 |
| Q-9 | 出題中の問題が属する領域・章・難易度を常時表示する |

> **Q-3 の意図**：クリックした瞬間に正誤が出ると、確信のない解答が「なんとなく押したら合っていた」で流れてしまう。
> 確定操作を挟むことで自分の解答に責任を持たせる。

### 3.5 結果表示（S-4）

| ID | 要件 |
|---|---|
| A-1 | 正答率を大きく表示し、3 段階で判定（合格圏内 85%以上 / もう一歩 70%以上 / 要復習 70%未満） |
| A-2 | 領域別・難易度別の正答率 |
| A-3 | 最も正答率の低い領域を「弱点」として提示 |
| A-4 | **今回「昇華」した問題数を表示**（以前間違えた問題に正解し、通常プールへ戻った数） |
| A-5 | 間違えた問題の一覧（自分の解答・正解・解説）を折りたたみで表示 |
| A-6 | 全問正解時は専用のメッセージ |
| A-7 | 合格ラインが協会非公表である旨を注記する |

### 3.6 学習レポート（S-5）

全セッション履歴を横断した分析。詳細は §5。

## 4. 学習アルゴリズム要件（本アプリの中核）

> **この章の仕様は移植元アプリで実運用しながら 3 回改善した結果である。変更しないこと。**

### 4.1 追跡するデータ

問題 ID ごとに以下を記録する。

| データ | 内容 | 更新契機 | 削除契機 |
|---|---|---|---|
| `lastSeen` | 最後に出題した日時（epoch ms）。**キーの有無が「出題済みか」も表す** | 解答のたびに上書き | 履歴クリア時のみ |
| `wrongIds` | 現在「間違えたまま」か | 誤答時に追加 | **正解時に削除** |
| `wrongCounts` | 累積の誤答回数 | 誤答のたびに +1 | **正解時に削除** |

> **移植元からの変更点**：移植元は `seenIds`（出題済み ID 一覧）を別に保持していたが、
> `lastSeen` のキー集合と実質同義で冗長だったため廃止した。旧 Gist データの `seenIds` は読み込み時に取り込む。

### 4.2 通常出題の選択優先度

**要件 L-1：直近に解いたばかりの問題を再出題しない。**

- 「未出題かどうか」の二値ではなく、**最後に出題してからの経過時間**で順位付けする。
- 未出題の問題は経過時間を最大（= 最優先）として扱う。

> 背景：当初は未出題フラグのみで制御していたが、全問を一巡した後は完全ランダムに退化し、
> 「直前のセッションと同じ問題ばかり出る」という体験上の問題が発生した。

**要件 L-2：苦手問題は通常出題では後回しにする。**

- 苦手問題（`wrongIds`）は、それ以外の問題だけで問題数を満たせない場合にのみ出題する。
- 苦手問題の復習は §3.3 の専用モードで行う設計とし、通常出題が苦手問題ばかりに偏るのを防ぐ。

### 4.3 昇華（Promotion）

**要件 L-3：苦手・要注意の問題に正解したら、通常の問題プールへ戻す。**

- 正解した時点で `wrongIds` から除外する。
- 正解した時点で `wrongCounts` も**削除**する（回数を減算するのではなく 0 にする）。
  - → 3 回間違えた問題でも、1 回正解すれば「要注意問題」から卒業する。
- 昇華した問題数を結果画面でフィードバックする（A-4）。

> 設計判断：累積回数を保持し続けると「一度つまずいた問題」が永久に要注意リストに残り、
> 克服したのにリストが減らないという体験になる。学習の達成感を優先し、正解を卒業条件とした。

**要件 L-4：昇華数の算出は、追跡データを更新する前の状態に対して行う。**

- 更新後の値を参照すると、正解した問題は既にリストから消えており昇華数が常に 0 になる。
- 本アプリでは更新前の状態を引数で受け取る純粋関数（`applyResults`）にして、順序ミスを構造的に防いでいる。

## 5. 学習レポート要件

全履歴を対象に、以下 13 種類を提供する。

| # | 指標 | 内容 |
|---|---|---|
| 1 | サマリ 4 指標 | 受験回数／累計解答数／平均正答率／ベストスコア |
| 2 | 連続達成 | 合格ライン以上を連続何回達成しているか（2 回以上で表示） |
| 3 | 正答率の推移 | **全履歴**を折れ線表示。3 回移動平均を重畳。件数に応じて軸目盛りとマーカー密度を自動調整 |
| 4 | 領域別の累計成績 | 正答率と初回→直近の増減 |
| 5 | **章別の累計成績** | 公式テキストの章ごとの正答率（移植元では実装できなかった軸） |
| 6 | 難易度別の累計成績 | 難易度ごとの正答率 |
| 7 | 難易度 × 領域ヒートマップ | 弱点の交差分析 |
| 8 | 日別の解答数 | 初回記録日から今日までを 0 埋めして棒グラフ表示（学習の継続性を可視化） |
| 9 | 目標達成率 | 合格ライン以上のセッションの割合 |
| 10 | 時間帯別正答率 | 朝／昼／夕／夜の 4 区分 |
| 11 | 領域別の成長 | 初回 vs 直近 5 回平均の比較 |
| 12 | 最近の受験 | 直近 10 件の一覧 |
| 13 | 履歴クリア | 二段確認付きの全データ削除 |

> **要件 RP-1**：正答率の推移は直近 N 件ではなく**全履歴**を表示すること。
> 学習の長期トレンドを見ることが目的のため、直近だけでは価値が出ない。

## 6. データ永続化・同期要件

### 6.1 ローカル保存

- localStorage に保存する。ブラウザを閉じても保持されること。
- 保存対象：学習履歴、出題追跡データ（§4.1 の 3 種）、同期設定。
- キー接頭辞は `webanalyst_`。`src/config.js` で一元管理する。

### 6.2 クラウド同期（任意機能）

| ID | 要件 |
|---|---|
| D-1 | GitHub Gist を保存先として、端末間でデータを同期できること |
| D-2 | 起動時に Gist から取得し、ローカルへ反映する |
| D-3 | セッション終了時に Gist へ保存する |
| D-4 | Gist へのアクセスに失敗しても、ローカルデータでアプリが動作すること（フォールバック） |
| D-5 | **同期対象には学習履歴だけでなく、出題追跡データ（§4.1）をすべて含めること** |
| D-6 | 保存フォーマットは後方互換を保つこと（旧形式・欠損キー・旧 `seenIds` を読めること） |
| D-7 | 同期を設定せずに利用を開始でき、その選択が永続化されること |

> **D-5 の背景**：移植元では当初、履歴のみを同期しており、PWA を再インストールして localStorage が消えた際に
> 「解いた問題の記録」が失われ、全問が未出題に戻る事故が発生した。追跡データも同期対象に含めること。

### 6.3 セキュリティ要件

| ID | 要件 |
|---|---|
| SEC-1 | **PAT・Gist ID をソースコードやコミットに含めないこと**（絶対厳守） |
| SEC-2 | 認証情報はユーザーが画面から入力し、localStorage にのみ保持する |
| SEC-3 | PAT は入力欄でマスク表示する |

## 7. 問題データの品質要件

| ID | 要件 |
|---|---|
| QD-1 | **選択肢の文字数を揃えること。正解が他より明らかに長い／短い状態を作らない** |
| QD-2 | 誤答選択肢も具体的な固有名詞・数値を含む「もっともらしい」内容にする |
| QD-3 | 全選択肢に解説を読む価値のある内容を持たせ、消去法だけで解けないようにする |
| QD-4 | 解説は「なぜ正解か」だけでなく「なぜ他が違うか」に触れる |
| QD-5 | 問題 ID は既存の最大値の続きから採番し、既存 ID を再利用しない |
| QD-6 | 同一問題内に完全に同じ文字列の選択肢を作らない（シャッフル時に正解位置が壊れる） |
| QD-7 | 公開されている試験ガイド・出題範囲に基づくオリジナル問題とし、実際の試験問題を複製しない |

> **QD-1 の背景**：移植元の初期の問題データでは、正解の選択肢だけが具体的で長く、
> 内容を知らなくても「一番長いものを選べば当たる」状態だった。
> 134 問を対象に全面修正した経緯がある。**本アプリは問題作成の初期段階からこの基準を適用している。**

### 7.1 文字数バランスの判定基準

```
比率 = max(正解選択肢の文字数) / max(誤答選択肢の文字数)

比率 >= 1.6         → 重度（必ず修正）
1.3 <= 比率 < 1.6   → 中度（修正推奨）
0.77 < 比率 < 1.3   → 許容
比率 <= 0.77        → 正解だけが極端に短い（修正）
```

**この基準は `tests/questions.test.js` で自動検証しており、違反があると `npm run build` が失敗する。**

### 7.2 配分の目標

| 章 | 初級 | 中級 | 上級 | 計 |
|---|---|---|---|---|
| 第1章 ウェブ解析と基本的な指標 | 20 | 18 | 10 | 48 |
| 第2章 事業戦略とマーケティング解析 | 14 | 14 | 8 | 36 |
| 第3章 デジタル化戦略と計画立案 | 14 | 14 | 8 | 36 |
| 第4章 ウェブ解析の設計 | 16 | 16 | 8 | 40 |
| 第5章 インプレッションの解析 | 18 | 16 | 10 | 44 |
| 第6章 エンゲージメントと間接効果 | 16 | 16 | 8 | 40 |
| 第7章 オウンドメディアの解析と改善 | 16 | 16 | 8 | 40 |
| 第8章 ウェブ解析士のレポーティング | 14 | 14 | 8 | 36 |
| **合計** | **128** | **124** | **68** | **320** |

`node scripts/stats.mjs` で現状の配分を確認できる。

## 8. 分類定義（Taxonomy）

### 8.1 領域（DOMAINS）— 章をまたぐ実務テーマ軸

| キー | ラベル | 対応章 |
|---|---|---|
| `metrics` | ウェブ解析の基礎と指標 | 第1章 |
| `strategy` | 事業戦略とマーケティング | 第2・3章 |
| `design` | 解析設計と計測環境 | 第4章 |
| `acquisition` | 集客・広告・エンゲージメント | 第5・6章 |
| `improvement` | 改善提案とレポーティング | 第7・8章 |

### 8.2 モジュール（MODULES）— 公式テキスト2026 の全8章

`ch1`〜`ch8`。本試験が章ごとにランダム出題される形式であるため、章単位の弱点把握が実利になる。

### 8.3 難易度（DIFFICULTIES）

| キー | ラベル | 定義 |
|---|---|---|
| `beginner` | 初級 | 用語・定義・計算式の単純適用 |
| `intermediate` | 中級 | 複数指標の比較、2ステップの計算、施策の使い分け |
| `advanced` | 上級 | 実務ケース判断、複合計算、複数選択 |

## 9. 非機能要件

| ID | 分類 | 要件 |
|---|---|---|
| N-1 | 対応環境 | モバイルブラウザ優先（縦画面）。PC ブラウザでも破綻しないこと |
| N-2 | PWA | ホーム画面に追加してネイティブアプリのように起動できること |
| N-3 | オフライン | 問題データはバンドルに含まれるため、Gist 同期以外はオフラインで動作すること |
| N-4 | 性能 | 問題数 500 程度まで、出題選択が体感遅延なく完了すること |
| N-5 | 配信 | 静的ホスティング（GitHub Pages）へ自動デプロイできること |
| N-6 | 表示 | ダークテーマ固定。長時間の学習で目が疲れにくい配色 |
| N-7 | 配置 | サブパス配信・ルート配信のどちらでも動作すること（`base: './'`） |
| N-8 | 品質 | 出題選択・昇華・集計・問題データを自動テストで検証すること |

### 9.1 既知の運用上の注意

| 事項 | 内容 |
|---|---|
| PWA キャッシュ | iOS の PWA はアイコンと静的アセットを OS レベルでキャッシュする。**アイコン変更時は再インストールが必要**（その際 localStorage が消えるため、Gist 同期の設定を促すこと） |
| デプロイ制約 | GitHub Pages 環境の保護により、`main` ブランチからのみデプロイ可能 |
| 合格ライン | 協会は公式に点数を公表していない。70% は通説値であり、その旨をアプリ内に明記している |

## 10. 用語集

| 用語 | 定義 |
|---|---|
| セッション | クイズを開始してから全問終了するまでの 1 回分の学習単位 |
| 領域（ドメイン） | 章をまたぐ実務テーマの分類（§8.1） |
| モジュール（章） | 公式テキストの章に対応した分類。領域とは独立した軸 |
| 苦手問題 | 直近の解答で誤り、まだ正解し直していない問題 |
| 要注意問題 | 累積で 2 回以上間違えている問題 |
| 昇華（Promotion） | 苦手／要注意の問題に正解し、通常の出題プールへ戻ること |
| 未出題 | 一度も出題されていない問題（`lastSeen` にキーがない） |
